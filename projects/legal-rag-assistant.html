Legal Knowledge Assistant

Firm knowledge sits in thousands of documents that nobody has time to read. This is a retrieval-augmented application that finds the relevant passages, summarises them, and cites where every claim came from — so the answer can be checked, not just trusted.

Type
Applied AI / internal tool
Role
Design & implementation
Stack
Python · embeddings · vector search · LLM
Principle
Citations, not confidence

The problem

Keyword search over a legal document store fails in a specific way: it matches words, but people ask about concepts. Someone searching for how a particular clause has been handled doesn't know which of five phrasings the drafters used. So the document that answers the question sits there, unfound, and the question gets re-answered from scratch.

Why RAG rather than a fine-tuned model

In a legal setting the requirement isn't fluency, it's attribution. A model that has absorbed the documents into its weights produces answers you cannot audit. Retrieval keeps the source visible: the system shows you the passages it used, and the summary is explicitly a summary of those passages. If the retrieval is wrong, that's visible too.

It also means the corpus can change without retraining anything — new documents are just indexed.

How it works

1. Ingestion and chunking

Documents are parsed and split into passages sized for retrieval, with overlap so a definition doesn't get severed from the sentence that uses it. Chunking on structural boundaries — sections and clauses rather than a fixed character count — keeps passages semantically whole. Each chunk carries metadata back to its document and location.

2. Embedding and indexing

Each passage is embedded into a vector and stored in a vector index. Semantically close passages end up close in that space, which is what lets a question phrased one way find a passage phrased another.

3. Retrieval

A query is embedded the same way, and the nearest passages are pulled back. Metadata filters narrow the search when the user already knows the scope. Retrieving a handful of strong passages beats retrieving many mediocre ones — precision at the top of the list is what determines answer quality.

4. Grounded generation

Retrieved passages go to the model as context with a strict instruction: answer from these passages, cite them, and say so when they don't contain the answer. "I don't have that" is a correct response, and the system is built to prefer it over a plausible guess.

# retrieval-augmented pipeline Firm documents │ parse → chunk on structure → attach metadata ▼ Embeddings ──────► Vector index ▲ User question ──► embed ──┘ │ ▼ Top-k passages + source metadata │ ▼ LLM, grounded prompt answer only from context; cite; abstain if absent │ ▼ Answer + citations every claim traceable to a document

Engineering decisions worth calling out

  • Abstention is a feature. In legal work a confident wrong answer is the expensive failure mode. The prompt and the UI both make "not in these documents" a first-class outcome.
  • Citations are mandatory, not decorative. Every response links to the passages behind it. That turns the tool from something you have to trust into something you can verify in ten seconds.
  • Chunk on meaning, not on length. Most bad RAG answers are bad retrieval wearing a good answer's clothes. Chunking strategy moved quality more than any prompt change.
  • Evaluate with real questions. A fixed set of questions with known-correct source documents makes retrieval quality measurable, so changes can be judged instead of vibed.

The right mental model isn't "AI that knows the law." It's a very good research assistant that always shows its sources and is comfortable saying it didn't find anything.

Results

  • ▸Concept-level search across firm documents, rather than exact-keyword matching.
  • ▸Answers arrive with citations, so verification takes seconds instead of a re-read.
  • ▸New documents are indexed, not retrained — the corpus stays current by default.

Where I'd take it next

Hybrid retrieval is the clearest win: combining vector similarity with keyword search catches the cases where an exact term — a statute number, a party name — matters more than semantic closeness. Beyond that, a reranking pass over retrieved candidates, and per-document access controls enforced at retrieval time so the assistant can never surface a passage the asker isn't cleared to read.
